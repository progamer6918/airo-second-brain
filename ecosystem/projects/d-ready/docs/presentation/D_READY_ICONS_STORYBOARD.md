# D-READY ICONS Storyboard

## Narrative Spine

```text
Manual fragmented monitoring
→ Need for governed early alert
→ Excel logic prototype
→ Pilot validation
→ Power BI operational target
→ Standard daily workflow
→ Continuous improvement
```

## Step 1 — Theme and Situation Analysis

### Purpose

Explain the business problem and scope.

### Canonical Message

Monitoring exists, but target, sales, stock, calendar, product, and color information are not integrated into one consistent readiness view.

### Required Evidence

Sanitized current-process flow or actual internal evidence in the presentation workspace.

## Step 2 — Set the Target

### Purpose

Define measurable improvement objectives.

### Target Areas

- monitoring coverage;
- status consistency;
- warning visibility;
- data quality;
- usability;
- daily operability.

Do not use an unmeasured time-saving number.

## Step 3 — Root Cause Analysis

### Root Cause

Fragmented source structures and non-governed calculation rules prevent consistent readiness classification.

### Fishbone Themes

People, method, system, data, measurement, and operating environment.

## Step 4 — Improvement Idea and Plan

### Selected Direction

```text
Excel Logic Prototype → Rule Validation → Power BI Operational Dashboard
```

### Visual Treatment

Use a dashboard teaser, not the full dashboard. Show a small KPI strip, one hierarchy sample, one status, and one Estimated Needs example using sanitized or clearly marked illustrative values.

Remove obsolete final-solution references to Macro/VBA.

## Step 5 — Implementation

Show:

- source-to-report flow;
- master mapping;
- calculation engine;
- Excel validation;
- Power BI model;
- one traceable case.

This is the first slide group that should show the full dashboard.

## Step 6 — Evaluation

Evaluate:

- source reconciliation;
- target allocation;
- warning accuracy;
- Excel and Power BI parity;
- usability;
- follow-up usefulness;
- operating effort.

Use actual evidence or a professional placeholder. Do not use dummy impact numbers.

## Step 7 — Standardization

Show:

- daily refresh SOP;
- role ownership;
- master-data governance;
- exception review;
- follow-up;
- access control;
- version and release control.

## Step 8 — Next Improvement

### Short Term

Lock rules, clean master data, build Power BI MVP, validate pilot.

### Medium Term

Automate ingestion, add follow-up, add historical trend, improve exception monitoring.

### Long Term

Scheduled refresh, role-level access, mobile layout, controlled dealer access, integration with broader Sales analytics.

## Evidence Policy

### Actual Evidence

Real screenshot, reconciliation result, validation case, follow-up, or time log.

### Placeholder

Use a clearly labeled frame describing the required evidence and replacement fields.

### Illustration

AI-generated or designed diagrams may explain architecture. They must never be presented as actual implementation evidence.

### Public ASB

Do not commit the original presentation or screenshots containing business data.
