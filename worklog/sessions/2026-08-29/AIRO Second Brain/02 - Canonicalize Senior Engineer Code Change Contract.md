# Canonicalize Senior Engineer Code Change Contract

## 🧩 Latar Belakang

Owner wanted AI-generated coding work to follow a senior-engineer minimal-complexity discipline, informed by useful Ponytail principles without making an external tool the ASB authority.

## 💬 Permintaan Owner

Canonicalize the design-locked Senior Engineer Code Change Contract after Council review.

## 🎯 Tujuan

Establish durable ASB-owned engineering rules for executable-code changes while avoiding code-golf, overengineering, unnecessary dependencies, and artificial review bureaucracy.

## ✅ Hasil

- Future executable-code changes have a canonical senior-engineering discipline.
- The target is minimum justified complexity, not minimum LOC.
- Ordinary diff review remains bounded inside the owning execution.
- Ponytail remains optional tooling rather than authority.

## 🧠 Keputusan Penting

- ASB owns the engineering contract.
- Ponytail plugin is not required for v1.
- Council is not a mandatory coding gate.
- No new .agents adapter is created in v1.

## 📍 Kondisi Akhir

Sesi selesai dengan status BERHASIL dan boleh lanjut: YA.

## ➡️ Berikutnya

Use the new contract on future executable-code changes; change it only from concrete usage evidence or a proven blind spot.
