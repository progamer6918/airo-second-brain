## 1. Problem Solved

Prior to this implementation, the AIRO Second Brain (ASB) ecosystem suffered from a **lifecycle mismatch** between runtime session execution and the human-facing Obsidian WorkDesk cockpit:
- **Root Cause**: `bin/airo-session` managed headless JSON state in `~/.local/state/airo/second-brain/<repo_hash>/active_session.json`. However, `state/active-session.md` (which transcludes into Obsidian `HOME.md`) was statically created or manually edited, without lifecycle coupling to `bin/airo-session start` or `bin/airo-session close`.
- **Symptom**: When runtime sessions closed cleanly (`ACTIVE_SESSION=NONE`), the Obsidian cockpit retained stale cards (e.g., `🟢 AIRO VPS Workbench`), creating false indicators of active work and confusing cross-device operators.

## 2. Final Architecture

The architecture enforces a strict 3-tier hierarchy separating truth from presentation:

```text
┌────────────────────────────────────────────────────────┐
│               1. PRIMARY: Runtime State                │
│  - Location: ~/.local/state/airo/second-brain/...      │
│  - Format: active_session.json                         │
│  - Authority: ABSOLUTE LIVE TRUTH                      │
└──────────────────────────┬─────────────────────────────┘
                           │ Deterministic hook on start/close
                           ▼
┌────────────────────────────────────────────────────────┐
│            2. SECONDARY: Markdown Projection           │
│  - Target 1: <repo_root>/state/active-session.md       │
│  - Target 2: /mnt/c/Users/Admin/AI_WORKSPACES/...      │
│  - Format: Markdown Active Card (🟢) / Idle Card (⚪)   │
│  - Authority: DERIVED READ-ONLY OPERATIONAL VIEW       │
└──────────────────────────┬─────────────────────────────┘
                           │ Transcludes via ![[active-session]]
                           ▼
┌────────────────────────────────────────────────────────┐
│            3. VIEWER: Obsidian Display Surface         │
│  - Interface: wiki/workdesk/HOME.md / HOME.md          │
│  - Environment: Windows Desktop & Mobile Obsidian Vault│
│  - Authority: PRESENTATION LAYER ONLY                  │
└────────────────────────────────────────────────────────┘
```

1. **Primary Truth**: Runtime JSON managed by `bin/airo-session`.
2. **Derived Projection**: `state/active-session.md` generated by `scripts/airo-session-projection-sync`.
3. **Presentation Surface**: Obsidian WorkDesk cockpit rendering the markdown embed.

## 3. Implementation Components

### 3.1 Synchronizer Script (`scripts/airo-session-projection-sync`)
- Executable Python helper supporting `update`, `reset`, and `status`.
- Generates human-friendly active cards (`### 🟢 <Project_Name>`) on `update` and canonical idle cards (`# ⚪ Tidak Ada Sesi Aktif`) on `reset`.
- Implements **dual-target workspace projection**: writes to both local repo root and canonical vault (`/mnt/c/Users/Admin/AI_WORKSPACES/airo-second-brain`) if running from scratch.
- Resolves project PRD wiki-links dynamically (`control/<project_id>` or `projects/<project_id>`).

### 3.2 Runtime Lifecycle Hooks (`bin/airo-session`)
- **`cmd_start` Hook**: Automatically calls `scripts/airo-session-projection-sync update --session-json ...` upon session initialization. Emits `PROJECTION_SYNC=START_UPDATED`.
- **`cmd_close` Hook**: Automatically calls `scripts/airo-session-projection-sync reset` upon verified session close. Emits `PROJECTION_SYNC=CLOSE_RESET`.
- **Fault-Tolerance Isolation**: Lifecycle hooks are wrapped in non-fatal exception guards (`try/except`). If filesystem projection fails, session lifecycle continues safely and emits `PROJECTION_SYNC_WARNING=YES`.

## 5. Deferred & Future Boundaries

1. **No Background Watcher Daemon Required**:
   - The synchronous lifecycle hook pattern in `bin/airo-session` completely eliminates the need for background polling, systemd watchers, or cron daemons.
   - Zero CPU/memory overhead when idle.
2. **Automation Bridge Deferred**:
   - Automated git push bridges and background file watchers remain explicitly out of scope and deferred.
   - Promotion to canonical repository continues under strict human-gated/Owner-approved promotion workflows (`docs/operations/AIRO_SESSION_WORKLOG_PROMOTION_SOP.md`).
